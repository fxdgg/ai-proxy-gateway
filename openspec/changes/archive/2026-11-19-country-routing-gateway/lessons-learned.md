# 归档经验记录：country-routing-gateway

归档时间：2026-11-19。全流程：方案设计 → 双评审（3 轮通过）→ 三任务并行实现 + tester 验证 + reviewer 审查（评分 A）→ 建议项修复 + 回归 → 最终审查（评分 A）。本变更是插件侧 `domain-country-routing` 的网关侧配套（第 3 个变更），补齐「数据文件 → 规则生成 → 路由生效 → 部署校验」链路。

## 技术决策

- **「命中为 0 阻塞建组」闸门采用分级判定 + 闸门后置**：开发环境无真实节点数据（`_merged.yaml` 为 `proxies: []`、仅模板数据可统计），与「任一国家命中 0 即阻塞建组」的硬闸门直接矛盾。决策：真实节点数据命中 0 → 阻塞建组；模板/示例数据或空产物 → 产出标注来源的「待部署环境复核」验证记录、不阻塞（正则不得因模板数据放宽）；最终闸门后置到部署环境 dry-run 复核（写入 DEPLOY.md 上线清单）。兼顾「本地能推进」与「上线前兜底」。
- **组名公式 `<code>-STICKY` 字符串拼接，禁止映射表**：7 国代码即组名后缀，映射表是多余间接层；组存在性校验运行时读取 `config.yaml` 真实组名集合，与拼接不冲突，反而保证校验覆盖真实配置。
- **跨仓库约束靠「锚定 + 一致性检查项」而非同步改动**：组名公式、`BROAD_DOMAIN_DENYLIST`、域名分段校验语义与插件侧 `popup.js` 约定强一致，但本仓库只消费导出格式、不改插件仓库；改 denylist 须同步插件常量，列为跨仓库一致性检查项。
- **verify.sh 组存在性判定用完整锚定模式 `^(JP|US|SG|TW|KR|GB|DE)-STICKY$`，禁止子串匹配**：裸 `DE`/`US` 子串会误命中 `NODE-POOL`、`BONUS-EXTRA` 等既有组名，导致把普通组误判为国家分流组强制非空检查。
- **API 模式 dry-run 只取节点名、排除组 key**：`/proxies` 返回对象同时含组与节点；组对象有 `.all` 字段、节点对象没有，用 `select(.value.all == null)` 过滤，避免 `JP-STICKY` 等组名在 7 国正则统计中虚高命中。

## 踩坑记录

- **shell 与 YAML 两层转义陷阱**：同一正则 `\b` 在两处写法不同——shell 单引号内写 `\b`（grep 词边界），YAML 双引号内写 `\\b`（转义后为 `\b`）。照搬双反斜杠到 shell 会导致 7 国命中全 0 并错误阻塞建组（第 2 轮辅审已实测复现）。任务书/代码中必须逐字标注「两层不同转义，不得互换」。
- **bash 3.2 兼容三坑（declare -A 缺失 / local 形参同名清空）**：无关联数组，同域名「重复保留末行」用 awk 两遍 + FNR 行号实现；`local VAR=$VAR` 形参与调用变量同名会在赋值前被清空，须换名传入。（多字节字符 bug 见 multi-airport 记录：awk 先转纯 ASCII 中间文件再逐行读规避。）
- **awk 组名解析必须排除注释行**：`config.yaml` 现存注释态示例块 `# - name: RELAY-POOL`，解析 `proxy-groups` 段组名集合时不过滤 `^[[:space:]]*#` 会把注释态组名误计入集合，导致「组缺失」检测失效（4.5 降级验证中通过临时注释 `DE-STICKY` 组同时验证了该口径）。
- **统计/提取口径须先剔除注释行**：注释掉的节点行（如 `# - {"name":"..."}`）不得参与命中统计，否则虚高命中掩盖真实缺口。
- **工作区 diff 混杂需按变更界定验证**：本变更与 multi-airport 同仓叠加，两批未提交改动混在同一工作区；验证/审查时须按 design「文件范围」表界定归属，避免误判另一变更的文件为本变更产物。

## 改进建议

- **数据文件格式约定应以示例行 + 操作约定落地**：`ai-domains-country.txt` 仅注释头 + 「清空后全量覆盖粘贴」约定，插件导出「覆盖粘贴」语义必须写在文件头，否则后续维护者不清楚追加/覆盖行为。
- **跨仓库联动变更建议先定稿接口契约再分仓实施**：本变更（网关侧）完全依赖插件侧已归档的导出格式约定；若两仓并行开发，先冻结「组名公式 / 数据文件两列格式 / 域名校验语义」三条契约，可避免三轮回审中反复对齐。
