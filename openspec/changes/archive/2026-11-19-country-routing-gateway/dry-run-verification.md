## 节点名提取口径

- 覆盖两种格式（与 build-config.sh 整段拷贝后产物格式一致）：
  1. 内联 JSON：`- {"name":"xxx",...}` —— awk 按 `"` 切分，取 `name` 字段后一个字段；
  2. 展开式 YAML：`- name: xxx`（换行缩进，引号可有可无）—— 行内 `#` 后内容视为行内注释剔除，再剥离首尾引号。
- 剔除注释行：行首 `^[[:space:]]*#` 的节点行不参与命中统计（避免被注释掉的节点误计入）。
- 规避 BSD grep `-oE` 多字节坑：提取全程用 awk 按引号切分，未使用 `grep -oE` 提取多字节内容。
- 提取逻辑已用含注释行/内联 JSON/展开式（带引号、无引号、行内注释）的临时样本逐项验证通过。

## 口径差异与 verify.sh（tasks 4.4）对齐说明（Reviewer 修复项归档）

- 本记录是 tasks 4.0 的验证记录，当时提取逻辑用 awk 按引号字段切分实现（含行内注释剔除），上节「提取逻辑验证通过」的结论针对 4.0 的 awk 口径，仍然成立。
- tasks 4.4 将同一口径落入 `scripts/verify.sh` 时，展开式 YAML 分支改用 sed 提取，初版对 `- name: xxx # 行内注释` 这类行整行不匹配（`[^"#]+` 后要求行尾空白），与本记录「行内注释样本验证通过」的声称存在口径差异。
- 修复（已合入 verify.sh）：展开式分支在提取前先剥行内注释 `sed -E 's/[[:space:]]*#[^"]*$//'`（引号内的 `#` 不受影响，如 `"US #1"` 不会被误剥），修复后 verify.sh 展开式分支与 4.0 的 awk 口径对齐。
- 修复后实测（API 不可达 → 本地降级链，临时样本跑完即删）：样本含展开式「带引号/无引号 + 行内注释」节点 3 条、内联 JSON + 行内注释 1 条、注释态节点行 1 条；7 国 dry-run 统计到 7 个节点（模板 3 + 样本 4，注释态未计入），命中 JP=2 / US=1 / SG=1 / DE=1（含行内注释节点），与 4.0 口径一致 ✅。
